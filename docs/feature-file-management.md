## 一、设计理念

### 1.1 核心理念

**用户不用管文件放哪里，助理自动整理。**

- 用户只需要把文件扔进来
- 助理自动：存储、分类、命名、索引
- 用户通过语义搜索找文件，不需要记住文件名

### 1.2 核心亮点

> **不需要记住文件名，只需要说出意思就能找到。**

## 二、文件入库方式

### 2.1 三种拖入方式

| 方式 | 操作 | 效果 | 适用场景 |
|------|------|------|----------|
| **直接拖入** | 无修饰键 | 文件移动到助理目录 | 用户不想保留原位置 |
| **Shift + 拖入** | Shift 键 | 复制一份，原文件保留 | 用户想两边都有 |
| **Ctrl + 拖入** | Ctrl 键 | 只记录路径，原位置不动 | 大文件、需要保持原位置 |

### 2.2 悬浮助手接收

```
用户拖拽文件到悬浮助手
    │
    ▼
检测拖入方式
    │
    ├── 直接拖入 → 标记为"移动"
    ├── Shift + 拖入 → 标记为"复制"
    └── Ctrl + 拖入 → 标记为"引用"
    │
    ▼
发送到后端处理
```

## 六、文档版本管理

### 6.1 设计理念

**文档自动版本管理，不需要用户每次选择覆盖或保留。**

- 同一文档多次入库 → 自动识别为新版本
- 保留所有版本历史
- 默认显示最新版本，可回溯历史版本

### 6.2 版本识别逻辑

```
文档入库
    │
    ├── 计算文件 hash
    │
    ├── 检测是否为同一文档的新版本
    │   ├── 文件名相似度 > 80%
    │   ├── 内容相似度 > 70%
    │   └── 判定为"同一文档的新版本"
    │
    └── 版本管理
        ├── 新文档 → 创建 v1
        └── 已有文档 → 创建 v2, v3...
```

### 6.2.1 相似度计算算法

**文件名相似度**：使用编辑距离（Levenshtein Distance）

```python
from difflib import SequenceMatcher

def calculate_filename_similarity(name1: str, name2: str) -> float:
    """计算文件名相似度"""
    # 移除扩展名
    name1 = Path(name1).stem
    name2 = Path(name2).stem
    
    # 使用 SequenceMatcher 计算相似度
    return SequenceMatcher(None, name1.lower(), name2.lower()).ratio()

# 示例
# "合同-张三-v1.pdf" vs "合同-张三-v2.pdf" → 0.92
# "合同-张三.pdf" vs "协议-李四.pdf" → 0.25
```

**内容相似度**：使用向量相似度

```python
from sentence_transformers import SentenceTransformer
import numpy as np

def calculate_content_similarity(content1: str, content2: str, model: SentenceTransformer) -> float:
    """计算内容相似度"""
    # 提取前 5000 字符（避免 token 过多）
    text1 = content1[:5000]
    text2 = content2[:5000]
    
    # 向量化
    emb1 = model.encode(text1)
    emb2 = model.encode(text2)
    
    # 余弦相似度
    similarity = np.dot(emb1, emb2) / (np.linalg.norm(emb1) * np.linalg.norm(emb2))
    
    return float(similarity)

# 示例
# 同一合同的两个版本 → 0.85+
# 两份完全不同的合同 → 0.30-
```

**版本识别规则**：

| 条件 | 判定 |
|------|------|
| 文件名相似度 > 80% **且** 内容相似度 > 70% | 同一文档的新版本 |
| 文件名相似度 > 80% **但** 内容相似度 < 70% | 不同文档，同名 |
| 文件名相似度 < 80% **但** 内容相似度 > 70% | 同一文档，改名了 |
| 两者都低 | 完全不同的文档 |

```python
def is_new_version(new_file: FileInfo, existing_files: list[FileInfo], model) -> tuple[bool, FileInfo]:
    """判断是否为已有文档的新版本"""
    
    best_match = None
    best_score = 0
    
    for existing in existing_files:
        # 计算相似度
        name_sim = calculate_filename_similarity(new_file.name, existing.name)
        content_sim = calculate_content_similarity(new_file.content, existing.content, model)
        
        # 判断逻辑
        if name_sim > 0.8 and content_sim > 0.7:
            # 同一文档的新版本
            score = (name_sim + content_sim) / 2
            if score > best_score:
                best_score = score
                best_match = existing
        
        elif name_sim < 0.8 and content_sim > 0.7:
            # 同一文档，改名了（也视为新版本）
            score = content_sim
            if score > best_score:
                best_score = score
                best_match = existing
    
    return best_match is not None, best_match
```

### 6.4 版本管理规则

| 规则 | 说明 |
|------|------|
| **自动识别** | 文件名相似 + 内容相似 → 新版本 |
| **保留所有版本** | 不删除旧版本，用户可回溯 |
| **默认显示最新** | 搜索/打开时默认是最新版 |
| **版本对比** | 可选功能，显示版本差异 |
| **照片不版本管理** | 照片每次都是独立的，不算版本 |

| 搜索类型 | 说明 | 适用场景 |
|----------|------|----------|

| **人物搜索** | 图谱关联 | "张三相关的文件" |

| **原文件名搜索** | 原名匹配 | 用户记得原文件名 |

**默认：混合搜索，自动融合多路结果。**

## 九、重复文件检测

### 9.1 检测逻辑

```
文件入库时计算 hash
    │
    ├── 相同 hash 已存在
    │   └── 判定为"完全相同的文件"
    │
    └── 文件名相似 + 内容相似
        └── 判定为"同一文档的新版本"
```

### 9.2 处理方式

| 情况 | 处理 |
|------|------|
| 完全相同（hash 一致） | 提示"该文件已存在"，跳过 |
| 新版本 | 自动版本管理，无需用户选择 |
