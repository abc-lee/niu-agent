# 照片处理 UI 交互需求

> 日期：2026-03-28
> 状态：待开发
> 优先级：下一个 Session 解决

---

## 背景

照片入库后，系统会识别出人脸并创建"未命名人物"。用户需要知道有待命名的人物，并能够方便地命名。

---

## 核心设计思路

**待办状态机制**：

```
后台事务完成（如照片入库）
    ↓
主 Agent 在聊天窗口汇报工作
    ↓
判断消息是否已读？
    ↓
未读（聊天窗口没打开）→ 悬浮窗状态机触发 → 显示红点
已读（聊天窗口打开过）→ 不触发
```

**优点**：
- 不需要轮询
- 复用现有消息系统
- 统一的待办机制（不仅限于照片）

---

## 待解决的核心问题

### 1. 聊天记录持久化

**现状**：每次重启都是全新的会话，聊天记录不保存。

**需求**：
- 聊天记录持久化存储
- 重启后恢复历史会话
- 支持消息的"已读/未读"状态

### 2. 消息未读状态判断

**需求**：
- 判断聊天窗口是否打开
- 判断消息是否被用户阅读
- 未读消息触发悬浮窗状态机

**问题**：
- 如何定义"已读"？窗口打开即已读？还是滚动到底部？
- 状态存在哪里？

### 3. 悬浮窗状态机

**需求**：
- 接收"有未读消息"的通知
- 显示红点或其他标志
- 点击红点打开聊天窗口

**问题**：
- 悬浮窗与主进程如何通信？
- 状态机触发方式？（事件？文件？HTTP？）

### 4. 后台事务汇报机制

**需求**：
- 后台任务完成后，通知主 Agent
- 主 Agent 在聊天窗口生成汇报消息
- 汇报消息可标记为"待办"

**场景**：
```
照片入库完成 → "已入库 3 张照片，检测到 7 人，其中 3 人未命名"
文档入库完成 → "已入库 文档.pdf 到 报告 分类"
人脸识别完成 → "检测到 2 张新人脸，是否命名？"
```

## 功能需求

### 1. 悬浮窗红点提醒

**触发条件**：
- 有未读消息（聊天窗口未打开）
- 消息包含"待办"标记

**显示**：
- 小女孩头像上显示红点
- 可选：显示数字（待办数量）

**交互**：
- 点击红点 → 打开聊天窗口
- 聊天窗口打开后 → 红点消失

### 2. 未命名人物处理流程

**用户操作**：
```
悬浮窗显示红点
    ↓
用户点击红点
    ↓
打开聊天窗口，主 Agent 说：
"刚才处理了 3 张照片，检测到 7 人，其中 3 人未命名，需要命名吗？"
    ↓
用户选择要命名的人物
    ↓
显示该人物的头像
    ↓
用户输入名字，完成命名
```

### 3. 人物头像展示

**需求**：
- 从原照片裁剪人脸区域作为头像
- 在聊天对话框中展示头像
- 用户确认后输入名字

**工具待实现**：
```python
def get_person_avatar(person_id: str) -> dict:
    """获取人物头像"""
    # 返回头像图片（Base64 或文件路径）
```

### 1. 前后端通信

**当前架构**：
```

    ↓ ?
主进程 (Go)
    ↓
photo-server (MCP Python)
```

**问题**：
- 悬浮窗如何与主进程通信？
- 主进程如何通知悬浮窗更新状态？

### 2. 数据存储

**需要持久化的数据**：
- 聊天记录
- 消息已读状态
- 待办事项列表
- 人物头像

**存储位置**：
- `~/.niu/chat_history.db`？还是 JSON 文件？

### 3. 状态同步

**需要同步的状态**：
