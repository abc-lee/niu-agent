# Niu 窗口与界面配置手册

本手册覆盖 Niu 桌面窗口的**位置/尺寸/外观**配置（含主对话窗的「迷你模式」），以及用户或主 Agent 需要调整窗口观感时的操作路径。

配置文件单一入口：`~/.niu/window-config.json`。

---

## 一、窗口一览

| 窗口 | 说明 | 是否可在配置中改位置/尺寸 |
|---|---|---|
| 主对话窗（Chat） | 主界面：对话、工具状态、子 Agent 标签页 | 是（`chat` 段） |
| 迷你窗 | 主对话窗的「迷你模式」形态：一个悬浮玻璃条 | 是（`chatMini` 段） |
| 精灵窗 | 桌面上的小女孩 | 是（`spirit` 段） |
| 便签窗 | 悬浮便利贴 | 是（`sticky` 段 + `stickySize`） |
| 设置窗 / 知识图谱窗 | 按需弹出的功能窗 | 否（每次居中弹出） |

---

## 二、`~/.niu/window-config.json` 结构与语义

文件位于用户目录（`~/.niu/`），首次启动程序会自动创建并写入完整默认值。**它是用户可手改的文件**：程序不会覆盖用户手改过的外观键（见第三节）。

### 2.1 `spirit` / `chat` / `sticky` / `stickySize` / `chatSessionId`

| 键 | 含义 |
|---|---|
| `spirit.x` / `spirit.y` | 精灵窗左上角的屏幕坐标 |
| `chat.x` / `chat.y` / `chat.width` / `chat.height` | 主对话窗**普通模式**的位置与尺寸 |
| `sticky.x` / `sticky.y` | 便签窗左上角的屏幕坐标 |
| `stickySize` | 便签窗尺寸（宽高同值） |
| `chatSessionId` | 上次使用的会话标识 |

### 2.2 `chatMini`（迷你窗外观与位置）

| 键 | 含义 | 默认值 |
|---|---|---|
| `x` | 构件（玻璃条）左边缘的屏幕 x | 无（首次进入迷你模式时按大窗位置推算） |
| `y` | 构件**底边**的屏幕 y（底边锚定：迷你窗只向上长高，底边不动） | 无（同上） |
| `width` | 构件宽度。消息幕布比它每边窄一个「胶囊半径」（= 输入条高度的一半），所以两者几何是联动的 | `408` |
| `idleOpacity` | 鼠标**不在**构件上时，玻璃**背景**的不透明度 | `0.4` |
| `hoverOpacity` | 鼠标**在**构件上时，玻璃背景的不透明度 | `0.5` |
| `idleContentOpacity` | 鼠标不在构件上时，**整个构件（含文字、按钮）**的整体不透明度；鼠标移上去时恒为完全清晰 | `0.35` |
| `maxHeightRatio` | 迷你窗高度上限 = 所在屏工作区高度 × 该值（超出部分在幕布内滚动） | `0.5` |

透明度取值范围 `0 ~ 1`：`0` 完全透明（看不见）、`1` 完全不透明。

**两个透明度是两层，互不替代**：
- `idleOpacity` / `hoverOpacity` 只管**背景玻璃**；
- `idleContentOpacity` 只管**内容（文字/控件）**。
- 想「静置时整体淡下去、鼠标上去全清晰」→ 调 `idleContentOpacity`；想「玻璃更实/更淡」→ 调 `idleOpacity`。

### 2.3 `blur`（点亮时的磨砂模糊）

| 键 | 含义 | 默认值 |
|---|---|---|
| `enabled` | 是否启用点亮时的磨砂模糊；`false` = 驱动层完全不加载模糊后端（零材质、零额外进程、零副作用） | `true` |
| `hoverOpacity` | 点亮时构件/幕墙内那层「白纱」（罩层）的浓度；`0` = 无白纱 | `0.08` |

**Windows 上的行为**：点亮（鼠标移到构件上 / autoPeek）时，**构件 ∪ 幕墙范围内**出现磨砂模糊——能看到身后内容的模糊影像；形状外完全透出（无黑圈、无底色泄漏、无模糊）。材质窗是**独立进程的零内容窗口**：不含任何 UI、不抢焦点、不进任务栏与 Alt+Tab。

**平台下限**：Windows **11 22H2（build 22621）及以上**才有材质；Win10 或更早版本 = 无模糊，其余观感与现状一致（不报错、不出现实色块）。

**无需预装运行时**：素材件已自包含（.NET 8 + Windows App SDK 随包），安装即用。

**观感说明**：Windows 的材质是系统「薄亚克力」，可调空间很窄（亮度层 0→1 仅约 11% 变化，且调不到「完全无材质」）；因此 Windows 与 macOS 的观感**不完全一致**，属平台限制而非配置问题。

**生效时机**：与其它配置相同——改完 `blur` 段必须**重启 Niu**。写盘规则上，`blur` 属**外观类键**：程序永不覆盖、缺失补默认、用户手改值原样保留。

## 三、写盘规则（重要）

1. **程序只写位置/尺寸类键**（`spirit.x/y`、`chat.x/y/width/height`、`sticky.x/y`、`stickySize`、`chatSessionId`、`chatMini.x/y`）。
2. **外观类键永不被程序覆盖**（`chatMini.width`、`idleOpacity`、`hoverOpacity`、`idleContentOpacity`、`maxHeightRatio`，以及用户自行添加的任何键）：**缺失时补默认值，已有值原样保留**。
3. **文件不存在时**（首次启动）程序写入一份完整默认值。
4. 因此：**用户手改的值不会丢**；反过来，想让某项回到默认，需要手动删除该键或改成默认值。

**生效时机**：配置文件在启动时载入，迷你窗透明度在**每次进入迷你模式时**读取一次 → **改完配置请重启 Niu**（只关窗重开不足以让主进程侧的位置/尺寸键重新读取）。

## 四、主 Agent 操作指引（用户要求调窗口观感时）

> 用户说"迷你窗太透/太实/看不见字/太宽/太窄/太高"时，按下表改 `~/.niu/window-config.json`，改完提示用户重启 Niu。

| 用户诉求 | 改哪个键 | 建议 |
|---|---|---|
| 「迷你窗太透了，看不清字」 | `chatMini.idleContentOpacity` 调大（如 0.35 → 0.6） | 鼠标移上去本来就全清晰，此项决定静置时是否也看得见 |
| 「玻璃太实，挡住后面内容」 | `chatMini.idleOpacity` 调小（如 0.4 → 0.25） | 只管背景，不影响文字 |
| 「想让悬停时更清楚」 | `chatMini.hoverOpacity` 调大（如 0.5 → 0.8） | 悬停时背景不透明度 |
| 「迷你窗太窄/太宽」 | `chatMini.width`（默认 408） | 消息幕布宽度会自动跟随（每边窄一个胶囊半径） |
| 「迷你窗太高，挡住屏幕」 | `chatMini.maxHeightRatio` 调小（如 0.5 → 0.35） | 上限为该比例 × 所在屏工作区高度 |
| 「迷你窗出现在屏幕外/位置不对」 | 删除 `chatMini.x` / `chatMini.y`（下次进入迷你模式自动落回大窗底部居中） | 也可直接写目标屏幕坐标（`y` 是**底边**） |
| 「点亮时那层白纱太浓/太淡」 | `blur.hoverOpacity` 调小/调大（如 0.08 → 0.04 / 0.15） | `0` = 无白纱；仅 Windows 11 22H2+ 生效 |
| 「不想要磨砂模糊（或低配机器上觉得卡）」 | `blur.enabled` 改 `false` | 完全回到无模糊观感，零额外进程 |

**操作纪律**：
- 手改前先**读**文件现状，只改被点名的键，**不要顺手"整理"或删除其他键**（用户手写的键一律视为有意为之）。
- 改完必须**明确告知用户重启 Niu**，否则不生效。
- 需要恢复默认时，把对应键改成上表默认值即可。

## 五、迷你模式使用说明（用户可见行为）

**进入/退出**
- 进入：主对话窗**标题栏最右侧、关闭按钮左边**的方块按钮。
- 退出：迷你条输入区右侧的还原按钮（⤢）；关闭按钮（✕）等同关闭主对话窗（下次点精灵重新打开，回到普通模式）。

**形态与交互**

| 行为 | 说明 |
|---|---|
| 长高 | 有新消息时幕布自动向上长（底边不动），高度上限为所在屏工作区的 `maxHeightRatio`；超出部分在幕布内滚动 |
| 手动调高 | 拖幕布**顶部中央的小横条**；拖过之后本次迷你会话不再自动长高，双击小横条恢复自动 |
| 移动窗口 | 按住幕布**顶部那条隐形拖拽带**（高约 18px，光标会变成四向箭头、拖动时变成手形）拖动 |
| 悬停点亮 | 鼠标进入构件（幕布或输入条）→ 整个构件变清晰；移开 → 变淡；**输入框聚焦期间移开鼠标也保持清晰**（打字时不会突然变暗） |
| 点击穿透 | 鼠标**不在**构件上时，点击会**穿给下面的窗口**——迷你窗不会挡住其它应用的操作 |
| 发送消息 | 迷你输入框回车或点 ↑ 发送，走**主对话**（即使当前激活的是子 Agent 标签页，也从主对话发出） |
| 显示内容 | 只显示**最新一条 Agent 消息**；Agent 处理中显示状态文本；无消息时显示占位文本 |
| 桌面跟随 | 迷你窗跟随当前桌面空间显示（**不含**全屏独占空间） |
| 平台差异 | Windows 无「桌面空间」概念，跟随项不产生效果，其余功能一致 |

## 六、常见问题

| 现象 | 说明与处置 |
|---|---|
| 迷你窗整体发白/不透明，点一下输入框才变透明 | macOS 透明窗口的合成滞后。**重启 Niu**；若每次都复现，请反馈（避免在进入迷你的同一瞬间叠加窗口级操作） |
| 窗口矩形被描了一圈边或阴影 | 系统给「比构件大的窗口矩形」画了阴影。程序在迷你态已关闭窗口阴影；若复现请反馈 |
| 迷你窗只能看见输入框、幕布点不亮 | 旧版把整个窗口设成了拖拽区（拖拽区不接收指针事件）。当前版本已改为顶部隐形拖拽带，构件全域可交互 |
| 想拖动窗口却拖不动 | 拖拽带在**幕布顶部约 18px** 那条（光标变四向箭头处）；另外主进程改动需要**重启 Niu** 才生效 |
| 鼠标移到留白处点击"没反应" | 这是点击穿透的预期行为：鼠标不在构件上时点击穿给下方窗口。把鼠标移到幕布或输入条上再点击 |
| Windows 打开迷你模式报错（`invalidateShadow is not a function`） | 旧版本缺陷（该 API 为 macOS 专属）。升级到当前版本即可 |
| 手改的透明度没生效 | 配置在启动时载入：**重启 Niu**；确认改的是 `~/.niu/window-config.json`（不是应用目录内的同名文件） |
